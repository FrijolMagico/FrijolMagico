# Activity occurrences — issue #192

## Objective and decisions

Allow workshop and talk activities to have zero or more optional scheduled occurrences. An occurrence has a calendar date (not restricted to edition days), Chile-local start time and positive duration. A provided occurrence is complete; an empty schedule is valid. Reject overlaps within the same activity and sessions ending after midnight. Location and capacity remain shared by activity. Public UI uses one card per activity with a list of occurrences, or “Fecha y horario por confirmar” when empty; never infer the first edition day.

For legacy workshops with a complete time and duration and exactly one edition day, backfill that date. Leave talks with missing start/duration unscheduled; leave ambiguous histories unscheduled. Keep registration per activity. Concurrent schedule changes require an original-snapshot conflict check with a reload prompt; unrelated edits preserve newer schedules. Do not execute a production migration without separate authorization. Preserve unrelated changes in the main worktree. Issue remains `status:needs-review`: no PR until approved.
